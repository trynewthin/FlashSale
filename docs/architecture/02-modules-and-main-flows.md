# 核心模块与主链路

## 1. 模块职责

| 模块 | 主要职责 |
| --- | --- |
| `user-rpc` | 用户认证、资料、密码、用户查询 |
| `product-rpc` | 商品信息、商品管理、普通库存与活动库存 |
| `order-rpc` | 普通订单、秒杀订单承接、支付确认、状态推进 |
| `seckill-rpc` | 秒杀活动、活动商品、购买入口、流量事件、活动订单视图 |
| `admin-rpc` | 管理员账号、角色、领域权限、审计日志 |
| `media-store` | 文件上传、列表、删除 |
| `ops-control` | 状态、任务、压测、容器和项目维护能力 |

## 2. 用户侧主链路

### 常规购买

1. 用户端通过 `user-gateway` 访问商品和订单接口。
2. `product-rpc` 返回可售商品信息。
3. 用户创建订单后由 `order-rpc` 管理订单状态。
4. 后续支付确认、取消、收货确认仍走 `order-rpc`。

### 秒杀购买

1. 用户端从 `user-gateway` 读取秒杀活动与活动商品。
2. 购买请求进入 `seckill-rpc`。
3. `seckill-rpc` 负责限流、活动库存控制和购买上下文。
4. 下单事件通过 Kafka 进入异步建单链路。
5. `order-rpc` 消费事件并创建订单，再把状态结果回流给秒杀侧。

## 3. 管理侧主链路

1. 管理员通过 `admin-gateway` 登录并获取后台能力。
2. 商品、订单、秒杀活动、管理员管理分别扇出到对应 RPC。
3. 领域权限由管理链路统一校验，避免前端直接伪造敏感字段。

## 4. 文件与媒体链路

1. 管理端通过 `media-store` 上传商品图。
2. `media-store` 负责写入共享目录。
3. `cdn` 只负责对外只读访问。
4. 这样可以把“管理上传”和“公开访问”职责分开。

## 5. 运维链路

1. `ops-control` 读取项目配置、Compose 描述和运行状态。
2. 运维端前端展示容器、任务、性能和实时状态。
3. `ops.sh` 与 `go run ./ops/cmd` 作为 CLI 入口承接日常维护操作。
