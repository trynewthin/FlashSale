# 当前范围、能力与边界

## 1. 当前已落地能力

### 业务能力

- 用户注册、登录、资料维护、改密、注销、用户查询。
- 商品管理、商品公开查询、普通库存与活动库存管理。
- 普通订单创建、秒杀建单、支付确认、取消、发货、收货确认、订单查询。
- 秒杀活动创建、上下线、活动商品配置、流量跟踪、活动订单视图。
- 管理员认证、角色、领域权限和审计日志。

### 工程能力

- Kafka 异步建单与事件回流。
- 秒杀入口限流、幂等控制、补偿处理、死信队列。
- etcd 服务发现。
- CDN 与 media-store 文件链路。
- Prometheus、Grafana、Jaeger 与项目内运维控制台。

### 展示能力

- 用户端可以展示商品与秒杀购买流程。
- 管理端可以展示商品、订单、秒杀活动和管理员配置。
- 运维端可以展示状态、任务、压测与容器拓扑。

## 2. 当前明确边界

为了避免文档再次失真，以下内容不被写成“已经完成”：

- 不宣称真实第三方支付集成已经落地。
- 不宣称已经具备生产级多地域、多集群部署能力。
- 不宣称已经形成完整的会员中心、地址中心等电商外围域。
- 不宣称 `ops-control` 是通用运维平台；它是为本项目定制的控制面。

## 3. 适合对外表达的项目亮点

- 不是孤立的秒杀接口，而是完整的业务与运维样板。
- 不只有业务前台，还有管理端和项目专用运维端。
- 不只关注“能下单”，还关注异步、补偿、排障和可观测性。
- 文档、部署、服务和前端都在一个仓库内闭环维护。

## 4. 后续演进方向

后续文档可以继续沿这些方向细化，但不必回到过去那种碎片化模块页：

- 进一步补强业务规则和数据边界。
- 收敛更稳定的部署基线和环境约束。
- 增强测试基线和压测结果沉淀。
