# 系统需求与定位

## 1. 目标问题

FlashSale 面向的是一个典型但不简单的业务场景：高并发秒杀活动并不只是一条抢购接口，它还要求商品管理、订单承接、管理端运营、运维观测和部署恢复都能串起来。

因此，这个仓库的目标不是做“单接口性能实验”，而是构建一套可持续演进的系统基础盘。

## 2. 目标角色

- 普通用户：浏览商品、参与秒杀、下单、确认支付、查看订单。
- 运营与管理员：维护商品、订单、秒杀活动、管理员账号与权限域。
- 项目维护者：部署基础设施、观察运行状态、执行 smoke/压测、处理异常。

## 3. 当前阶段定位

当前代码处于“基础阶段已完成”的状态，强调的是系统骨架、关键业务链路和维护能力已经齐备。

- 已有完整业务面：用户、商品、订单、秒杀、管理端。
- 已有完整运行面：Docker Compose、Nginx、可观测性组件、运维控制台。
- 已有完整前端面：用户端、管理端、运维端。

## 4. 为什么采用这一形态

相比把所有逻辑堆在一个单体应用里，当前仓库选择以业务域拆分 RPC 服务，并用网关承接外部入口，主要是为了：

- 让用户、商品、订单、秒杀、权限管理的职责边界更清晰。
- 让秒杀这条高竞争链路能独立演进限流、异步、补偿和监控能力。
- 让运维能力不只是外部附属脚本，而是项目自身的一部分。
